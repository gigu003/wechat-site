## 官方资料

1. NCBI API 页面  
   https://www.ncbi.nlm.nih.gov/home/develop/api/  
   支持：E-utilities 是访问 Entrez（含 PubMed）的公共 API，由搜索、链接和记录获取等工具组成。  
   不能推出：API 返回的每篇研究都可靠，或一定提供全文。

2. NCBI E-utilities 使用说明  
   https://www.ncbi.nlm.nih.gov/books/NBK25499/  
   https://www.ncbi.nlm.nih.gov/books/NBK25501/  
   支持：ESearch 返回 UID；ESummary 返回摘要性记录；EFetch 返回指定数据库的记录。PubMed ESearch 单次结果检索存在前 10,000 个 UID 的限制，批量任务需使用 History/EDirect 或拆分查询。  
   不能推出：所有第三方 MCP 都完整实现这些能力。

3. PubMed 帮助  
   https://pubmed.ncbi.nlm.nih.gov/help/  
   支持：可用 `[ti]`、`[tiab]`、`[au]`、`[mh]`、`[pt]`、`[dp]`、`[pmid]` 等字段标签；字段标签会影响自动词语映射。  
   不能推出：一个看似合理的自然语言查询已经覆盖所有同义词和主题词。

4. NCBI 使用政策  
   https://www.ncbi.nlm.nih.gov/home/about/policies/  
   支持：无 API key 时脚本请求通常不超过每秒 3 次；应提供 `tool` 和 `email`。E-utilities 文档说明 API key 默认可提高到每秒 10 次。  
   不能推出：可以无视原文版权批量复制摘要或全文。

5. MCP 官方规范  
   https://modelcontextprotocol.io/specification/2025-06-18/server/tools  
   https://modelcontextprotocol.io/specification/2025-06-18/server/index  
   支持：MCP server 可以向模型暴露 tools；客户端应呈现工具调用并保留人类控制。  
   不能推出：任何自称 MCP server 的第三方代码都经过安全审计或由数据提供方背书。

6. MCP Registry 说明  
   https://modelcontextprotocol.io/registry/about  
   支持：Registry 仍是 preview；登记元数据不代表项目得到策展或背书。  
   不能推出：登记或在 GitHub 可见就等于适合生产环境。

## Zotero Local API 与 Zotero MCP

1. Zotero 官方 Local API 文档  
   https://www.zotero.org/support/dev/web_api/v3/local_api  
   支持：近期 Zotero Desktop 在启用本机通信后，可通过 `localhost:23119/api/` 读取本地数据库；本地读取不经过网络、无 Web API 频率限制。Zotero 10 及以后也支持需要授权的写请求。  
   不能推出：任何第三方 Zotero MCP 都由 Zotero 官方维护，或默认只具有读取权限。

   支持：该项目 README 展示了本地模式 `ZOTERO_LOCAL=true`，以及搜索条目、读取元数据和附件等能力。

## 文章中的事实边界

- “能查到 PMID/DOI”只解决身份与可追溯性，不自动证明研究质量。
- PubMed 主要提供书目信息与摘要；全文可用性取决于 PMC、开放获取或机构订阅。
- MCP 是连接层，不是数据库；结果质量仍取决于查询、工具实现、返回是否截断以及人工核验。
- Zotero MCP 检索到的是用户库中的已有条目；本机库可能存在重复、缺失字段或导入错误，也可能根本没有目标文献。
- 引用前要核对标识符、题名/作者/年份/期刊，以及原文是否真的支持所写结论。
